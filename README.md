# Anonymazer

**Anonymazer** — сервис автоматизированной анонимизации чувствительных данных в текстовой информации.

Система предназначена для обнаружения и маскирования персональных и конфиденциальных данных с использованием настраиваемых правил и паттернов. Anonymazer предоставляет API для интеграции с внешними приложениями и позволяет обрабатывать текстовые данные, снижая риск раскрытия чувствительной информации при их использовании.

## Основные возможности

- **Обнаружение чувствительных данных** — поиск персональной информации с помощью специализированных детекторов и регулярных выражений.
- **Анонимизация текста** — автоматическая замена обнаруженных значений на маскирующие обозначения.
- **Модульная архитектура** — разделение логики обнаружения и обработки данных на независимые компоненты.
- **Статистика обработки** — подсчёт обнаруженных элементов по категориям.
- **История операций** — сохранение исходных и обработанных данных, а также статистики выполнения в PostgreSQL.
- **REST API** — взаимодействие с сервисом через HTTP-запросы.
- **API-документация** — описание и тестирование методов через Swagger / OpenAPI.

## Поддерживаемые типы данных

| Тип данных | Пример исходного значения | Результат анонимизации |

### Компоненты системы

- **Controllers** — принимают HTTP-запросы, выполняют валидацию и возвращают результаты обработки.
- **Services** — реализуют обнаружение чувствительных данных, разрешение пересечений найденных совпадений и анонимизацию.
- **Detectors** — специализированные компоненты для обнаружения отдельных типов данных.
- **Models** — определяют структуру входящих запросов, ответов и обнаруженных элементов.
- **Data** — обеспечивает взаимодействие с PostgreSQL через Entity Framework Core.
- **Migrations** — обеспечивают версионирование и обновление структуры базы данных.

## Принцип работы

Обработка данных выполняется в несколько этапов:

1. Клиент отправляет текст через REST API.
2. API проверяет входные данные.
3. Сервис анонимизации передаёт текст специализированным детекторам.
4. Детекторы находят чувствительные значения и определяют их позиции.
5. Система разрешает пересечения найденных совпадений.
6. Обнаруженные значения заменяются маскирующими обозначениями.
7. Формируется ответ со статистикой обнаруженных данных.
8. Результат и история обработки сохраняются в PostgreSQL.
9. Клиент получает обработанный текст и статистику.

## API

### Анонимизация текста

`POST /api/Anonymization`

Метод принимает текст, обнаруживает чувствительные данные и возвращает результат анонимизации.

**Пример запроса:**

```json
{
  "text": "Email: user@example.com, phone: +7 (999) 123-45-67"
}
```

**Пример ответа:**

```json
{
  "originalText": "Email: user@example.com, phone: +7 (999) 123-45-67",
  "anonymizedText": "Email: [EMAIL], phone: [PHONE]",
  "emailsFound": 1,
  "phonesFound": 1,
  "passportsFound": 0
}
```

При передаче пустого текста API возвращает `400 Bad Request`.

### Документация API

Интерактивная документация доступна через Swagger UI:

```text
http://localhost:5149/swagger
```

Фактический адрес определяется конфигурацией запуска приложения.

## Хранение данных

Для хранения истории операций используется PostgreSQL.

Таблица `AnonymizationHistory` содержит:

| Поле | Описание |
|---|---|
| Id | Уникальный идентификатор операции |
| OriginalText | Исходный текст |
| AnonymizedText | Результат анонимизации |
| CreatedAt | Время выполнения операции |
| EmailsFound | Количество обнаруженных email |
| PhonesFound | Количество обнаруженных телефонов |
| PassportsFound | Количество обнаруженных паспортных данных |

Взаимодействие с базой данных реализовано с помощью Entity Framework Core. Для управления схемой базы данных используются миграции.

## Установка и запуск

### Требования

- .NET SDK 10.0
- PostgreSQL
- Git

### Получение исходного кода

```bash
git clone https://github.com/Bodyabulder34/Anonymazer.git
cd Anonymazer
```

### Создание базы данных

В PostgreSQL создайте базу данных:

```sql
CREATE DATABASE anonymizer_db;
```

### Настройка подключения

Для локальной разработки конфиденциальные параметры подключения хранятся с помощью .NET User Secrets.

Инициализация:

```bash
dotnet user-secrets init
```

Настройка строки подключения:

```bash
dotnet user-secrets set "ConnectionStrings:DefaultConnection" "Host=localhost;Port=5432;Database=anonymizer_db;Username=postgres;Password=YOUR_PASSWORD"
```

Замените `YOUR_PASSWORD` на пароль пользователя PostgreSQL.

Не храните реальные пароли и другие секреты в исходном коде или Git-репозитории.

### Применение миграций

```bash
dotnet ef database update
```

### Запуск приложения

```bash
dotnet run
```

После запуска API будет доступен по адресу, указанному в терминале.

## Безопасность

При работе с чувствительными данными особое внимание уделяется защите исходной информации и контролю доступа к ней.

Текущая реализация предусматривает хранение исходного и анонимизированного текста в PostgreSQL. Поэтому база данных должна использоваться с соответствующими ограничениями доступа.

Конфиденциальные параметры подключения в локальной среде разработки хранятся отдельно от исходного кода с помощью User Secrets.
